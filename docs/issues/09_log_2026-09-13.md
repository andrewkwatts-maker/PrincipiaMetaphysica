### Root cause located: the octonions are correct, the 3-form is the wrong tensor

The defect above has a precise cause, and it is not a badly chosen convention.

**The octonion algebra is genuine.** `multiply()` was tested against the defining
properties rather than inspected: **norm-multiplicative to 4.4e-16**
(|xy| = |x||y|, the composition-algebra property) and **alternative to
5.8e-16**. Whatever is wrong, the multiplication is not it.

**The 3-form implied by that multiplication IS a G2 form.** For imaginary units
e_i e_j = -delta_ij + C_ijk e_k with C totally antisymmetric, and that C *is*
the associative 3-form. Read straight off the product, phi[i,j,k] = (e_i e_j)_k
has **dim ann = 14**, and equals the tensor the class already exposes as
`multiplication_constants`.

**The framework deliberately keeps two tensors**, and says so in the source:

    _C_geom   all (+1) on the seven Fano triples   "used for geometry"      dim ann 6
    _C_mult   the same triples, (1,3,5) flipped    "normed division algebra" dim ann 14

with a comment above `OCTONION_TRIPLES` conceding "the sign on triple (1,3,5)
**must be -1** for norm multiplicativity". But **G2 = Aut(O)**, so the
associative 3-form and the multiplication structure constants are the *same*
tensor. There is no separate geometric orientation to choose, and maintaining
two is the defect rather than a convention. They differ in exactly one sign, on
(1,3,5) — verified across all 35 components — so **the correct form was already
in the codebase**, under a different name.

This means the correction is **derived, not imported**: the framework's own
algebra selects which of the 16 admissible G2 forms is the right one, which a
comparison against a textbook convention could not do.

### Why three consistency checks all passed

The all-(+1) convention is replicated in **three independent tables**:
`G2_TRIPLES` (g2_differential.py), `FANO_TRIPLES` -> `_C_geom` (octonions.py),
and an inline `local_phi` (octonionic_mixing.py). Every cross-check compares two
of those copies, so agreement was guaranteed by construction.

To be precise about what those checks are and are not: `from_e8()` asserts the
octonion-derived phi equals `_standard_phi()`, and that compares **two
independently maintained tables**, not a tensor against itself. It is a real
check — it would catch a typo in either table. It cannot catch a wrong
convention replicated in both, which is what happened.

The one check with discriminating power in principle is the Hitchin identity
`phi_iab phi_jab = 6 delta_ij`, and it **cannot see the difference either**: the
product is 6 * I for both forms. So the stated justification for the all-(+1)
choice — that it is "the correct convention for metric derivation via Hitchin's
formula" — is true of the form it rejects as well, and therefore justifies
nothing.

**The generalisable lesson:** mutual agreement among copies is not evidence.
Three tables agreeing established only that they were copied from one another.

### A hazard in the switch-and-compare architecture itself

Running a fork branch **writes to shared build artifacts**. `AutoGenerated/` is
gitignored, so nothing polluted can reach a commit — but the next run reads the
previous branch's `parameters.json`, and the framework's own tests compare
against it.

This produced 10 phantom failures that looked exactly like a code regression:
`test_observable_dispositions` and `test_registry_paths` failed in the full
suite while passing in isolation and passing under `git stash`. Rebuilding on
the adopted branch cleared them and the suite returned **1825 passed, 0 failed**.

**So every two-branch measurement must rebuild between branches**, or the second
number is meaningless. Recorded because it will otherwise recur at every future
fork comparison, and because a contaminated run is indistinguishable from a real
regression without the stash test.

#### What the invariance actually reveals

This is the more important half, and it is not good news.

phi can be replaced by a tensor in a **different GL(7) orbit** — not a
rescaling, not a relabelling, a genuinely different 3-form, one a G2 form and
one not — and **not a single published number moves**.

So no published quantity is sensitive to the sign assignment on the Fano
triples, and therefore none is sensitive to whether phi is a G2 form at all.
The parameters that carry `g2_structure` or `octonion` provenance are all

    geometry.face_moduli_T1..T4   geometry.shadow_asymmetry_delta_T
    geometry.racetrack_stability  geometry.n_aligned_pairs
    geometry.V_cb                 geometry.J_CKM

The precise statement is therefore **not** "phi feeds nothing". It is that the
outputs depend on the Fano **incidence structure** — which seven triples carry
the form — and not on the **orientation** that makes it G2. That is exactly
consistent with everything else measured this pass: R1 to R4 and the arc flag

which triples, not which signs.

**This is the 24-layer diagnosis one level in.** There, the lattice supplied an
integer and no geometry. Here, the G2 structure supplies a combinatorial
incidence pattern and no differential geometry: the holonomy claim, the torsion
classes, the Lambda^2 and Lambda^3 splittings all sit on an object whose

Two readings, and the register does not choose between them:

1. The framework is really a **combinatorial** theory of the Fano plane, and the
   G2 language is descriptive rather than load-bearing. If so it should say that,
   and the correction is free because nothing depended on the geometry anyway.
2. The G2 content is meant to be load-bearing and the machinery that would make
   it so — the metric, the torsion, an actual Y_7 — is absent, so there is
   nothing yet for the orientation to act on. If so the invariance is a
   statement about how much is unbuilt, not about what is true.

Either way, **correcting phi costs nothing measurable**, which makes the ruling
cheap rather than risky. It remains the author's: whether the G2 holonomy claim
should rest on an object that moves no output is not a question code can settle.

### The half-shift enumeration is tractable, and here is its size

Scoped, since the pass above proved the half-shift data is load-bearing rather
than a refinement.

Conjugating a generator g by a translation T_t sends its shift vector
s -> s + (eps - 1) t componentwise. On a **flipped** coordinate eps = -1, so
s -> s - 2t and 2t covers all of R/Z: the shift is **removable**. On a **fixed**
coordinate eps = +1, so s is **invariant**.

So the meaningful data is a half-shift on each generator's FIXED line only --
3 coordinates, s in {0, 1/2} for g^2 = 1, hence 2^3 = 8 choices per generator.
Presenting the orbifold needs 3 generators, a non-collinear triple in F_2^3, of
which there are **28** of the 35 triples.

    raw enumeration = 8^3 x 28 = 14,336 assignments
    reduction by one global translation = a 2^7 = 128 search per assignment

Total well under 10^7, so this is direct enumeration rather than a search
problem. The A6 gate still applies before any novel (b_2, b_3) is read off it:
the pipeline must first reproduce Joyce's published Betti numbers for his known
(Z/2)^3 examples.
