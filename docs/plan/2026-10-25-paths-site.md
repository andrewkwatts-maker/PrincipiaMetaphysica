## Design

### 1. One catalogue of branches (data, in the engine)
`src/metaphysica/theories/pm/lineage/branches.yaml`, curated from the archaeology
(`docs/plan/paths/archaeology/a{1,2,3}.{md,jsonl}`). Two kinds of entry:

- **versions**: the theory's lineage: `id, label, era, parent, status
  (trunk | branch | dead_end | active), framing, why, worked[], failed[],
  key_results[{quantity, value, source}], evidence[]`. The trunk runs from the 2025
  documents to the D-015 active path.
- **options**: answers to fork questions that the engine has no switch for. Each one is
  added to an existing fork, or to a new declared fork, as a `VariantOption` with
  `implemented=False`, `restored_from=<sha:path>`, a status (considered/disabled) and
  its reason. Nothing is runnable until P8 restores it, but every branch is on the graph.

Rule: every value and reason carries its source (sha:path or document#section). No
invented numbers.

### 2. A thin PM theory adapter
`src/metaphysica/theories/pm/__init__.py` exposes `THEORY` (test-ground `Theory`):
switches = `variants.FORKS` + the catalogue's declared-only options/forks; the selection
store reads `variants.active_selection()` (read-only until P3A's `active.yaml`); the
decision log points to the site's `docs/DECISION_LOG.md`.

### 3. Lineage in the generic graph (`path_graph/2`, a superset of /1)
- Node type `version`; edge types `evolves_to` (trunk/branch) and `superseded_by`.
- `testground/lineage/{model,load,layout}.py`: generic; time-ordered lanes in integer
  coordinates, computed in Python (the site and the app draw the same positions).
- The exporter writes one `AutoGenerated/path_graph.json` with both views:
  **Lineage** (versions over time, gold trunk) and **Switches** (fork columns, option
  rows, gold polyline through the active options).

### 4. Per-path results: computed, then published as patches
- A **path** is a configuration. The published set is the active path plus every
  *single-option deviation* of an implemented option (one fork switched). Combinations
  are drawn but marked "not computed".
- Runner: one `metaphysica.build --fast` per path into a scratch root, sequentially
  (the engine's output junction is shared), with `METAPHYSICA_VARIANT_<FORK>` set.
- `testground/results/patch.py` (generic): a structural diff of each artifact against
  the main build → RFC 6902 ops keyed to the published main file, with its sha256.
  Volatile keys (timestamps, durations, run ids) are excluded.
- `theories/pm/results.py`: a per-path summary: scoreboard counts, χ², gates, the
  certificate claims that hold, the n_gen target fact, the key predictions, and the
  count of changed values. An empty patch marks the switch **inert** ("declared, but
  no simulation reads it yet"): this is the generalisation audit.
- Published: `AutoGenerated/paths/index.json` (manifest) and
  `AutoGenerated/paths/<path_id>/{summary,patch}.json`.

### 5. Site
- `Pages/paths.html`, `js/pm-paths-page.js`, `css/pm-paths.css`: the two views with
  pan/zoom, the gold best path, an inspector with BUYS/COSTS/ruled-out text, decision
  links, worked/failed, and a results panel comparing the path with main.
- `js/pm-path-context.js`: a classic script, first in every page's `<head>`. It holds the
  selected path (`?path=` then `sessionStorage`), and overlays `fetch` for
  `/AutoGenerated/<file>.json`: base, then the path's patch, refused on a sha256
  mismatch. Off main, a sticky bar reads: "Viewing path X (status). These are this
  path's results, not the theory's predictions. [Why] [Return to main path]". On main, a
  small gold "Main path" chip links to the Paths page. Historical versions are
  selectable on the Paths page only (archival results with sources); site pages stay
  on main for them, and the bar says so.

### 6. Governance
- D-021 pre-registered before any path is published (D-013 still governs labels:
  nothing off-path is presented as a prediction; main is the default and the share
  link default).
- "Best" means the D-015 active path. The D-019 assessment has not run, so no ranking is
  shown. The per-path data are shown as data, with the note that fit is only a
  tie-break under the decision rule.
