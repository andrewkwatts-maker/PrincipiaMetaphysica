## Goal
A reader opens **Paths**, sees the theory's branching history and its switches with the
main (best) path in gold, selects any path, and reads why it was rejected or considered,
what works, what doesn't, and its computed results against main. "View across the site"
switches every page to that path's results, behind a clear bar, and "Return to main
path" restores main from anywhere.

## Files you own
- `W/js/pm-path-context.js`: a **classic** script (no modules) that runs first in every
  page's `<head>`. It covers contracts §6: selection (`?path=` → sessionStorage
  `pm.path` → main), the `fetch` overlay with a sha256 check (crypto.subtle; when it is
  unavailable, treat the result as a mismatch), RFC 6902 apply (add, remove and replace
  with ~0/~1 unescape), the sticky bar off main, the gold "Main path" chip on main, and
  `?path=` kept on internal `<a href>` clicks while a path is selected. Load
  `paths/index.json` once per page and cache the patches per page load. Handle
  `fetch(string | URL | Request)` and URLs that are relative (`../AutoGenerated/x.json`,
  `AutoGenerated/x.json`), root-relative and absolute same-origin, ignoring the query
  string. Expose `window.PMPath = {current(), select(id), returnToMain(), applyPatch(doc,
  ops), index()}` for the Paths page.
- `W/Pages/paths.html`, `W/js/pm-paths-page.js`, `W/css/pm-paths.css`. The Paths page
  has:
  - A short header: gold = the main path (the D-015 active path, which generates the
    paper). No ranking is shown, because the D-019 assessment has not run. Link D-021.
  - Two views, toggled: **Lineage** (versions over time, eras on the x axis) and
    **Switches** (fork columns, option rows). Both are SVG drawn from the precomputed
    integer positions in `AutoGenerated/path_graph.json` (`layout.lineage` and the /1
    switches layout), with no client-side layout. Colours come from `legend`. They
    support pan and zoom (wheel, drag, +/−/reset buttons, keyboard), with focusable nodes.
  - An inspector for the selected node.
    - A version shows: framing, why, worked, failed, key_results with sources, evidence,
      and the tag "Archival: not re-run".
    - An option shows: summary, consequence, rationale sections (BUYS/COSTS/...),
      status, decision refs, kill condition, restored_from, and "not implemented" when
      it applies.
    - A computed path (matched by `fork--option`) adds a results panel from
      `paths/<id>/summary.json`: the scoreboard against main, χ², gates, n_gen, the
      certificate, and a key_values table (value / main / experimental). It also shows
      the inert notice or the not_computed reason, plus [View this path across the site]
      → `parameters.html?path=<id>` and [Return to main path].
  - A path list (searchable, grouped by fork; the status chip shows inert/changed
    counts) that also deep-links via `#<path_id>`.
  - A `<noscript>` table of the paths.
  - Under 800px wide, the inspector stacks under the graph.
- `W/js/pm-header.js`: add a "Paths" NAV_LINKS entry (minimal diff).
- Every `W/Pages/*.html` and `W/index.html`: insert one `<script src=".../js/pm-path-context.js"></script>` line as the
  **first** child of `<head>`, with the right relative prefix. Pages without the header
