## 1. Find candidates (in `src/metaphysica/simulations/` and `generators/`)
Look for:
- Literals of the theory's discrete numbers used as choices, not as derived results:
  24, 43, 7 (Joyce seeds), 72, 288, 163, 26, 13.
- `if`/`elif` chains or dicts keyed by a mode, method, route, variant or version string, where
  the key isn't read through `resolve()`.
- Parallel versions of one observable (`*_v18`, `*_v19`, alternative formula ids) where code
  picks one by hand.
- Module-level flags or constants that select between implementations.
- Registry rows that a consumer recomputes instead of reading. These are shadows: one value,
  two derivations. `scripts/audit_shadow_derivations.py` KNOWN_CONFLICTS (theta_13, n_s, m_higgs)
  are such cases.
Skip derived constants with one value by derivation, and test tolerances.

## 2. Classify each candidate
- **F (fork):** there are at least two defensible alternatives and outputs depend on it. Name
  the fork, its options and the adopted option. Say whether it duplicates an existing
  catalogue fork whose value it ignores (that is a bug: it should read that fork).
- **S (shadow):** a value recomputed instead of read. Give both sources.
- **D (dead):** the choice exists but nothing downstream reads it.
For F and S, name the parameters.json rows it reaches, if you can tell statically.

## 3. Output (`hidden_forks.md`)
- A table: id, file:line, class, the alternatives, rows reached, existing fork it should read
  (if any).
- Then a short ranked list of the 10 worth doing first. Rank by the number of rows reached and
  whether it contradicts a declared fork.

## Report (≤ 15 lines)
- The counts by class.
- The top 10, one line each.
- Any candidate that contradicts a catalogue fork today.
