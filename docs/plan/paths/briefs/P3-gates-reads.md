## 1. Gates: generic, in testground
- `testground/switches/model.py`, field `Fork.applies_when: Tuple[Tuple[str, str], ...] = ()`.
  The fork acts only when, for every fork named, the selection picks one of the listed
  options. Options for the same fork are OR'd and different forks are AND'd, the same
  grouping as `requires`.
- New `testground/switches/gates.py`:
  - `validate_gates(forks)` refuses unknown forks or options, self-reference, and a cycle;
  - `gate_open(forks, fork_id, selection)` treats a missing fork as its `default()`;
  - `canonical(forks, selection)` drops a fork's entry when its gate is closed, and entries
    equal to the default. It iterates to a fixed point, bounded by `len(forks)` passes, and
    raises if that bound is passed.
- `Configuration` digests and `configurations/enumerate.py` use `canonical`, so a gated-off
  difference is one configuration. A selection with no gated-off entries keeps its current
  digest; test that.
- Tests on the toy theory: add one gated fork to the toy theory if it has none, and say so
  in the report.

## 3. The read tracker
- In the variants selection module, `resolve()` counts reads per fork in a module-level
  counter, kept separate from `_FORCED`. Add `reads() -> Dict[str, int]` and `reset_reads()`.

  `closed_gate_reads[fork]` instead (exposed the same way).
