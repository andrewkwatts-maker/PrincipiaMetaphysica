## 1. `testground sweep --theory T --runs-dir D`
Builds a list of selections, then runs each with the existing worker, resumably.
- `--singles`: every option of every fork, one deviation from the adopted default, after
  `canonical()`; selections that canonicalise to one id run once. `--only FORK[=OPT] ...` filters.
- `--joint K` (K ≤ 3): read the finished single runs in D, take `audit.footprints` and
  `audit.interaction_sets(k ≤ K)`, drop sets the theory's constraints refuse, run the rest.
- `--sample N --seed S`: `audit.sample_selections` over compatible full paths.
- `--dry-run` prints the selection ids and the count, and runs nothing.
- Resume: skip a run whose stamp has the current engine fingerprint; rerun a stamp from another
  fingerprint (the rule in `sweep.py`'s docstring). `--jobs` defaults to 1. If the theory's run
  shares state between runs (PM's `AutoGenerated` junction; find out how the worker isolates a
  PM run), refuse `--jobs > 1` for that theory with a clear message rather than racing.
- Each finished run keeps the theory's outputs, including `fork_reads.json` and build status.

## 2. `testground audit --theory T --runs-dir D [--out report.json] [--md report.md]`
Loads the runs in D (skipping and listing stale-fingerprint ones) and writes `audit.audit(...)`:
- classes (`equivalence_classes`), no-op options (`no_op_options`), interaction sets;
- non-additive rows: for each joint or sampled run, `predict` from the singles vs its rows;
- reads: `reconcile_reads` from each run's `fork_reads.json` against the gates;
- failures: group runs by failed build step and reason (what `triage.py` does). Add this to the
  report as a new key only if `audit/report.py`'s schema allows it; otherwise bump its schema
  version and update its test.
- Exit code non-zero when there is a closed-gate read or a non-additive row, so CI can gate on it.
