# Brief V1: the path graph glows on reasonable alternatives (2026-10-28)

Owner direction: "The branching graph on the website glows on alternative paths that are
reasonable." The selected path keeps its gold. Paths the ranking marks `reasonable` (other than
the selected one) glow. Everything else stays as it is.

## Where it is
- The graph data comes from `testground/graph/build.py` (and `layout.py`). It writes
  `AutoGenerated/path_graph.json`, whose option nodes carry `attrs.on_active_path`.
- The page is `website/js/pm-paths-page.js` (gold path at about line 89, nodes at about 170,
  inspector at about 315), with `website/Pages/paths.html` and its CSS.
- The input is `AutoGenerated/path_ranking.json`, whose contract is in `track_s_selection.md`.
  Lane S1 produces it in parallel, so build against a fixture of the contract.

## Work
1. **graph/build.py:** if `path_ranking.json` is present, set `attrs.reasonable`, `attrs.rank` and
   `attrs.delta_chi2` on the path and option nodes of each reasonable path. Also mark the edges
   along those paths. If the file is absent, set no attributes and the page renders as today.
2. **pm-paths-page.js and CSS:**
   - Reasonable alternatives glow, using an SVG `feGaussianBlur` filter or a CSS drop-shadow in
     a colour distinct from gold, defined as a theme token.
   - The inspector shows rank, Δχ² and why the path is reasonable (the `reasonable_rule`).
   - The legend gains a "reasonable alternative" entry, and the path list marks them.
   - Respect `prefers-reduced-motion`: a static glow, no pulsing.
3. Tests:
   - a Python test that a fixture ranking yields the attributes and a missing ranking yields none;
   - if the repo has JS tests, one for the glow class.

## Acceptance
