# Paths: JSON contracts (2026-10-25)

Shared by E1 (engine) and E2 (site). Governed by D-021. A field without data is `null`
and never filled with an invented value. All files are UTF-8 with LF line endings.
`path_id` is `main`, or `<fork>--<option>`, and matches `^[A-Za-z0-9_]+(--[A-Za-z0-9_]+)?$`.

## 1. Catalogue: `metaphysica/theories/pm/lineage/branches.yaml` (`metaphysica.lineage/1`)
```yaml
schema: metaphysica.lineage/1
sources: "..."                  # where the entries came from
versions:                       # the theory's lineage, oldest first
  - id: twotime_10_2            # [a-z0-9_]+, unique
    label: "(10,2) two-time framework"
    era: "2025-07"              # YYYY-MM or YYYY-MM-DD; orders the lanes
    parent: null                # a version id, or null for a root
    status: trunk               # trunk | branch | dead_end | active (exactly one active)
    superseded_by: null         # a version id, or null
    framing: "..."              # what the theory said at this point
    why: "..."                  # why it was adopted, considered or abandoned
    worked: ["..."]
    failed: ["..."]
    key_results: [{quantity: "...", value: "...", source: "doc#section or sha:path"}]
    evidence: ["sha:path", "Downloads/<file>#<section>"]
    maps_to: ["fork.option"]    # engine options this version corresponds to (may be empty)
    branches_considered: [{title, answer, status, why, source}]  # passed through to attrs
forks:                          # declared-only forks (no engine switch yet)
  - {id: "...", question: "...", source: "...", notes: "..."}
options:                        # declared-only options (implemented: false)
  - {fork: "<existing or declared fork>", id: "...", summary: "...", consequence: "...",
     status: considered | disabled | rejected, restored_from: "sha:path", source: "...",
     kill_condition: "", decision_refs: []}
```
Load fails early on: unknown parent or superseded_by, a cycle, not exactly one `active`,
an unknown status, a duplicate id, or an option for an undeclared fork.

## 2. Graph: `AutoGenerated/path_graph.json` (`metaphysica.path_graph/2`)
A superset of /1 (see `testground/schemas/path_graph.schema.json`). Additions:
- node `type: "version"`, `id: "version:<id>"`, `class` = its status, `label`, `status`,
  `attrs` = every catalogue field except `id`, plus `era_order` (int),
  `rationale` = `{summary: why, sections: [{key:"worked"|"failed", heading, body}]}`.
- edge types `evolves_to` (parent → child) and `superseded_by` (old → new), `class` =
  the target's status; edge `maps_to` (version → `option:<fork>.<option>`).
- declared-only options appear as ordinary option nodes with `class: "not_implemented"`
  and `attrs.implemented: false`, `attrs.restored_from`.
- `layout.lineage = {bbox:[x0,y0,x1,y1], eras:[{label, x}], lanes:[{id, label, y}],
  positions: {"version:<id>": [x, y, w, h]}}`: integers, computed in Python. The trunk
  and active versions share lane 0, with branches and dead ends in lanes below.
  The existing /1 keys (`layout.columns`, `layout.bands`, `layout.bbox` and node positions)
  are the **switches** view, unchanged.
- top level `views: ["lineage", "switches"]`.

## 3. Path manifest: `AutoGenerated/paths/index.json` (`metaphysica.paths/1`)
```json
{"schema": "metaphysica.paths/1", "theory": "pm", "main": "main",
 "generated": "2026-10-25T12:00:00Z",
 "engine": {"version": "x.y.z", "commit": "abc1234"},
 "base": {"parameters.json": "<sha256 hex of the published main file>"},
 "paths": [
  {"id": "main", "kind": "main", "label": "Main path", "status": "active",
   "selection": {"<fork>": "<option>"}, "deviation": null,
   "computed": true, "inert": false, "changed_values": 0, "changed_artifacts": [],
   "why": "The D-015 active path: ...", "decision_refs": ["D-015"]},
  {"id": "chi_eff_route--constant_144", "kind": "deviation",
   "label": "chi_eff_route = constant_144", "status": "considered",
   "deviation": {"fork": "chi_eff_route", "option": "constant_144", "from": "k3_reading",
                 "question": "<fork question>"},
   "summary": "<option summary>", "consequence": "<option consequence>",
   "computed": true, "inert": false, "changed_values": 12,
   "changed_artifacts": ["parameters.json"], "decision_refs": [],
   "build": {"exit": 0, "secs": 158}}],
 "not_computed": [{"id": "...", "fork": "...", "option": "...",
                   "reason": "build failed (exit 1)" }]}
```
Each entry also carries `failed_steps` (ids of failed non-required build steps; `[]` when none).
A path is in `not_computed` only when a *required* step failed (PM: `run_all_simulations`);
`reason` is that step's `reason` from `build_status.json`, else the last exception line of
`<runs>/<path_id>.log`, else `build failed (exit N)`.
`AutoGenerated/build_status.json` (`metaphysica.build_status/1`, written by every build;
`--keep-going` continues past failed steps):
`{"schema": "...", "failed_steps": [{"id", "title", "exit", "reason"}], "keep_going": true}`;
`reason` is the step's last `...Error: ...` line or null. Like `variants.json`, it is bookkeeping.

`status` is the option's status in `variants.py` (active | considered | disabled), or
`rejected` from the catalogue. `inert` is true exactly when every op is in `variants.json`
(switch bookkeeping, not a result); `changed_values` and `changed_artifacts` exclude it.

## 4. Path summary: `AutoGenerated/paths/<path_id>/summary.json` (`metaphysica.path_summary/1`)
```json
{"schema": "metaphysica.path_summary/1", "path": "<path_id>",
 "scoreboard": {"PASS": 0, "MARGINAL": 0, "TENSION": 0, "FAIL": 0, "SKIP": 0},
 "chi2": {"value": 0.0, "dof": 0} ,
 "gates": [{"id": "...", "passed": true, "detail": "..."}],
 "certificate": [{"id": "...", "holds": true}],
 "n_gen": {"value": 3, "target": 3, "holds": true},
 "key_values": [{"id": "<parameter id>", "volatile": false, "label": "...", "unit": "...",
                 "value": 0.0, "main": 0.0, "experimental": 0.0, "sigma": 0.0}],
 "changed": {"count": 12, "by_artifact": {"parameters.json": 12}},
 "failed_steps": [{"id": "...", "title": "...", "exit": 1, "reason": "..."}],
 "unverified_files": [],
 "inert": false}
```
Any field the main build does not produce is `null`. `key_values` lists every parameter
whose value differs from main (up to 40, largest relative change first), and always
includes the headline parameters named in `theories/pm/results.py`. A parameter whose value
is volatile (§5) never ranks as moved; a headline one carries `volatile: true`.

## 5. Patch: `AutoGenerated/paths/<path_id>/patch.json` (`metaphysica.path_patch/1`)
```json
{"schema": "metaphysica.path_patch/1", "path": "<path_id>",
 "files": {"parameters.json": {"base_sha256": "<hex>", "ops": [
    {"op": "replace", "path": "/parameters/alpha_inv/value", "value": 137.1}]}},
 "excluded_keys": ["generated_at", "..."]}
```
- The ops are RFC 6902, restricted to `add`, `remove` and `replace`, with RFC 6901
  pointers (`~0` for `~`, `~1` for `/`). Objects are diffed per key. An array whose
  length differs is replaced whole; otherwise it is diffed per index.
- Only files whose ops are non-empty are listed. Keys are paths relative to
  `AutoGenerated/` (for example `parameters.json`, `foo/bar.json`).
- `base_sha256` is the sha256 of the published main file's bytes. The site refuses the
  patch (and shows main, with a notice) when it does not match.
- Volatile keys are excluded: the set of keys (by pointer, with array indices as `*`)
  where the main build (the published full build) differs from **any** twin build of
  main (`--volatile-run runs/active runs/active2`, both fast). This catches run-to-run
  noise and build-mode differences, because the deviation runs are fast builds.
  The theory may also declare stochastic subtrees (`theories/<t>/results.py`
  `STOCHASTIC = {file: (pointer, ...)}`), which are volatile even when the twins agree
  (PM: `statistical_rigor_report.json` `/jacobian_analysis`, a random-entry stub).

## 6. Site behaviour (E2)
- Selection: `?path=<id>` wins, then `sessionStorage["pm.path"]`, then `main`. An
  unknown id → main.
- Overlay: `window.fetch` wrapper for same-origin `.../AutoGenerated/<file>.json`. When the
  selection is not main and `patch.files[file]` exists, it fetches the base text,
  checks its sha256 (crypto.subtle) against `base_sha256`, parses it, applies the ops,
  and returns a `Response` with the patched JSON. On a mismatch or error it returns
  the base, and the bar shows "results unavailable for this file: showing main".
- Bar (off main): sticky, top of page. "Viewing path **<label>** (<status>). These are
  this path's results, not the theory's predictions." [Why] → `paths.html#<id>`,
  [Return to main path] clears the selection and reloads without `?path`. Main
  pages show a small gold "Main path" chip linking to the Paths page.
- Internal links keep `?path=` while a path is selected.
