# Track S: dynamic path selection, path gates, glowing alternatives (2026-10-28)

## Owner direction (2026-10-28)
- "Branching solutions: we dynamically select the path based on best output; the branching
  graph on the website glows on alternative paths that are reasonable."
- "The 72 gates are a bit rusty; a simple number isn't really valid. Just gates based on the
  selected path." This settles decision 7 and its hidden-site part (decision 10): a gate reads
  the value the selected path gives, never a literal b3.
- What "best" means (owner's choice): **consistency first, fit breaks ties.** The rank is
  lexicographic:
  1. internally consistent (switch_search verdict; it uses no measurements);
  2. fewest failing master-action ladder checks;
  3. fewest failing gates among the gates that apply to the path;
  4. lowest χ² against measured anchors (the tie-break).

  The paper names the selected path and how many paths were searched, so a fitted choice is
  disclosed as one. The rule in `switch_search.py` and `variants` changes from "never rank" to
  "rank by consistency, disclose the fit".

## Contract: `path_ranking.json`
S1 writes it, the build publishes it to `AutoGenerated/path_ranking.json`, and V1 reads it.

```json
{
  "schema": "path_ranking/1",
  "rule": "lexicographic: consistent, ladder_failed, gates_failed, chi2",
  "reasonable_rule": "consistent, ladder_failed <= selected, delta_chi2 <= 4",
  "searched": 69,
  "selected": "<path_id>",
  "rows": [
    {"path_id": "<digest>", "selection": {"<fork>": "<option>"}, "rank": 1,
     "consistent": true, "ladder_failed": 0, "ladder_total": 0,
     "gates_failed": 0, "gates_applicable": 0,
     "chi2": 0.0, "dof": 0, "delta_chi2": 0.0,
     "reasonable": true, "missing": []}
  ]
}
```

- `path_id` matches the run directory digest and the `paths/index.json` ids.
- `missing` names any input that a run didn't publish. Never fill it in silently.
- χ² uses only rows that are predictions. It excludes INPUT, CALIBRATED and CALIBRATION_CHECK
  rows.
